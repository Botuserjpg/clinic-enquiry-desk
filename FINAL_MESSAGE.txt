FINAL MESSAGE — Clinic Mission Control
======================================

Repository: https://github.com/Botuserjpg/clinic-enquiry-desk
Live static demo: https://botuserjpg.github.io/clinic-enquiry-desk/
Branch: main
Latest pushed commit at time of writing: 350eb8e
Documentation commit for this file: see "Git status" below.

A local, explainable triage workspace for FICTIONAL general-practice clinic
enquiries. Emergency wording always wins and tells staff to relay 000. A human
approves every reply, and approval never sends anything. This is a
demonstration, not a medical device, and it must not be used with real patient
information.


1. WHAT CHANGED
---------------

Design system and shell
- styles.css — hand-written design system: dark navy / teal / amber / red
  tokens, light theme, tabular numerals, responsive layout, print styles,
  prefers-reduced-motion handling, visible focus. No CDN, external font,
  framework or build step.
- index.html — mission-control shell: hero, live status strip (mode badge,
  clinic clock, in-hours state, queue size), intake panel, Decision Pipeline,
  emergency panel, dashboard, audit/history, footer, command palette and
  auto-demo overlay. Inline SVG icon sprite.
- theme.js — theme persistence and toggle, HTTP(S)-only manifest injection,
  HTTPS-only service-worker registration.

Triage and presentation
- app.js — rewritten against the new DOM while keeping the existing static and
  server logic: masking, localStorage with in-memory fallback, hash-linked
  events, emergency acknowledgement gate, human approval gate, history and
  integrity rendering, pipeline stage builder, refill identity checklist.
- mission.js — dashboard and interactions: role swimlanes, arrival timeline,
  hourly heatmap, priority donut, backlog ageing, SLA gauge, median
  time-to-first-approval, labelled time-saving assumption, live simulation,
  command palette (Ctrl+K or /), optional Web Speech voice input, skippable
  six-step auto-demo, integrity chain.
- classifier.js — unchanged rule order; exposes matched category term, matched
  prompt-review word, red-flag phrases and rule order as evidence.

Server
- server.js — Node standard-library server: static files with extra MIME types,
  same-origin JSON API, masking, hash chain, and a new
  POST /api/enquiries/:id/acknowledge route with validation and duplicate
  protection. Injects the CLINIC_SERVER_MODE marker.

Pages and PWA
- handover.html, handover.js — printable shift handover sourced from the local
  event log, ordered by urgency.
- prompt-lab.html — honest prompt provenance; missing rounds 01/02 are marked
  TODO (owner), not invented.
- safety.html — plain-English safety case.
- limits.html — known limits and what a real deployment would need.
- manifest.webmanifest, sw.js, icons/clinic-icon.svg,
  icons/clinic-maskable.svg — PWA assets. The service worker is static-only,
  never caches /api/, and is registered only on HTTPS.

Docs and submission artefacts
- README.md — live/repo links, "Try it in 60 seconds", two-mode table, Pages
  steps, assessment mapping, test counts, screenshots, owner TODOs.
- BUILD_LOG.md — real problems and fixes under "Wow round", with times and
  commit SHAs.
- PROMPTS.md, prompt_history/03_wow_prompt.md — the Wow-round prompt saved
  verbatim; missing earlier originals marked TODO (owner).
- AI_USAGE.md — honest AI-use statement plus owner reflection questions.
- VIDEO_SCRIPT.md — ~3-minute script with [SAY IN YOUR OWN WORDS] placeholders.
- SUBMISSION_EMAIL.md — email draft to jobs@gokulinfocare.com with a TODO for
  the video link.
- docs/screenshots/ — six reviewer screenshots captured from headless Chrome.
