SAFETY CASE · PLAIN ENGLISH

Safety is a set of gates, not a claim

This is a demonstration of a triage workflow for fictional enquiries. It does not diagnose or give medical advice. This page explains the safety choices in the prototype and what they do not prove.

Immediate danger? Call 000. The demo tells staff to relay the 000 instruction whenever emergency wording is detected. It does not contact the sender or emergency services.

1 · Emergency wording wins

The red-flag scan runs before category and urgency rules. A match forces the category to Emergency, the priority to Emergency wording, and a relay-now target. The UI shows the exact phrase that fired.

Why: a routine booking rule must never bury a message that says “cannot breathe”.

2 · A human approves every reply

A draft is prepared, but the reply stays locked behind an explicit staff action. Emergency replies stay locked until the 000 instruction is acknowledged. Approval records a staff name and timestamp; it does not send anything.

Why: the prototype supports judgement, it does not replace it.

3 · Synthetic data only

Every example is fictional. The app masks common phone, email, Medicare-style and date patterns before local storage. There is no account system, no remote database and no runtime model API.

Why: a hiring demo must never become a place where real patient information is entered.

4 · Local-first and inspectable

Static mode uses localStorage with an in-memory fallback and makes no application network calls. Server mode writes to a local Node file. The audit view links events with a hash chain and can verify it.

Why: reviewers can inspect behaviour without a backend, and the demo still works on GitHub Pages.

5 · No medical advice

The draft replies are administrative acknowledgements. They do not diagnose, recommend treatment, or tell a person what medication to take. The refill path is routed to a GP and includes an identity checklist, not a clinical decision.

Why: triage is not treatment.

6 · Accessibility and motion

The app supports keyboard navigation, a skip link, visible focus, a command palette, semantic labels and a light/dark theme. prefers-reduced-motion disables the pulsing emergency glow and stage animations. Read-aloud only runs after a user clicks the button.

Why: a safety tool that some staff cannot use is not safe.

What this safety case does not claim

  • It does not establish clinical performance or real-world safety.
  • Phrase matching can miss emergencies and can flag benign text. See Limits.
  • The hash chain detects some local edits; it is not a security boundary, authentication system, or tamper-proof audit log.
  • The evaluation numbers describe agreement with a small synthetic fixture, not performance on patients.
