LIMITS · WHAT THIS DEMO CANNOT DO

Honest limits

The prototype is intentionally simple. The list below is part of the design, not a footnote. If this were a real clinic tool, each item would need an owner, a control and a test.

Phrase matching is literal

The classifier checks whether configured phrases appear in the lower-cased message. It has no grammar, context, sentiment or clinical reasoning. “No chest pain” contains “chest pain”, so it is flagged. That is over-triage, not understanding.

Mitigation in the demo: the matched phrase is shown, staff approve every reply, and emergency replies stay locked until acknowledged.

Negation and look-alikes

“No shortness of breath” and a “chest pain awareness poster” both trip the red-flag rule. The auto-demo deliberately shows these false positives. A production system would need curated patterns, negation handling and clinical governance.

Multi-intent messages

Only the first matching category in the configured order is reported. A message that asks for a script, an appointment and billing help becomes one category. A human must notice the rest.

No clinical validation

The evaluation reports 12/12 category, priority and red-flag agreement on a small synthetic fixture, and 4/4 emergency recall (100%). These are rule-consistency checks, not sensitivity, specificity, clinical validation or evidence of safety with real patients.

No identity, auth or access control

Anyone with the local browser profile can read the history. There is no login, role-based access, encryption at rest, audit of viewers, or secure transport configuration. The hash chain can expose some edits but is not a security boundary.

Storage can disappear

Static mode keeps events in localStorage and falls back to memory if storage is blocked. Clearing site data, using a private window, or switching browser profiles loses the history. Server mode writes a local JSONL file and is not a database.

No message is ever sent

Approval records a human decision. The prototype has no email, SMS, phone or messaging integration. This is deliberate: a demo must not contact a real person.

No runtime AI

Triage is deterministic and runs locally. There is no model API, no prompt sent to a provider, and no learning from entered text. AI tools were used to help build the project; that is documented in AI_USAGE.md.
